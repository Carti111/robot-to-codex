# 使用与常见问题

## 配对前

电脑端只接收兼容固件的 CVI1 文字事件。普通出厂小智固件、相同版本号或相同主控型号不代表实现了此协议。先向固件作者确认是否支持本项目的安全配对和原生听写模式。

同一局域网、互相可访问；访客 Wi-Fi、AP 隔离、VPN 或多网卡路由可能影响发现。无需公网 IP、端口转发、MCP URL 或 OpenAI API Key。

首次使用生成本机 TLS 身份，保存于 `%LOCALAPPDATA%/CodexVoiceInputRobot/secrets/robot-wifi.bin`，受当前 Windows 用户加密保护。不要复制到另一台电脑。机器人开启新配对后绑定新电脑；旧绑定应在新绑定保存成功前保留。

## 每天使用

打开程序，等“已连接”；在 Codex 选聊天并点输入框。说“开启语音输入”，口述正文，等机器人提示音，看草稿；确认后单独说“发送”。发送不退出模式。单独说“退出模式”后恢复正常聊天。

“增加发送按钮”“这个函数退出模式后保存”等长句保留为正文。当前应用支持的固定短语以 `RobotTextSession.Command` 为准，固件必须使用一致的分类规则。

正文反馈由机器人根据电脑完成确认播放，电脑不播放声音。普通聊天是否发声、如何唤醒，由机器人固件负责。

右上角 × 关闭界面但程序留在托盘；“退出程序”或托盘退出停止接收。听写过程中直接退出程序只会让机器人暂停，建议先说退出口令恢复聊天，再退出应用。故障不会自动把普通正文变成机器人聊天请求。

## 搜不到设备

1. 确认机器人已经开启配对，码未过期。参考配置为 120 秒；五次失败后关闭窗口。
2. 确认是同一局域网且没有访客隔离。
3. 只运行一份电脑端。重开程序通常只唤起已有窗口。
4. 检查防火墙对当前 EXE 路径的规则。移动便携目录后，旧路径规则不适用于新路径。
5. 检查机器人回复是否为合法 JSON，协议字段与端口是否正确。ESP-IDF nano printf 可能不支持某些 64 位格式，请使用 JSON 库或经过验证的格式。

必要时在管理员 PowerShell 手动运行：

```powershell
.\scripts\configure-firewall.ps1
# 自己指定便携程序位置：
.\scripts\configure-firewall.ps1 -ProgramPath 'D:\Apps\RobotToCodex\CodexVoiceInput.exe'
```

脚本仅为该程序添加局域网入站规则：TCP 45831、UDP 45832，以及来自配对发现 UDP 45833 的回复。规则作用域 LocalSubnet；不更改网络类别、不关闭防火墙。构建、测试与应用本身不自动执行此脚本。

## 显示连接但没有正文

“连接”只代表协议握手和心跳成功。确认已经说开启口令、最终 STT 从机器人发出、设备接受本轮授权、前台是 Codex 且焦点在输入框。模型口头说“已开启”不代表本地模式确实开启。

前台不是 Codex 时应用拒绝注入。Codex 若以管理员权限运行，而应用是普通权限，Windows 可能阻止输入；优先让二者都以普通用户运行。

输入错误或确认中断后检查屏幕，不要盲目重复说发送。程序不会自动补发旧消息；可能已写入文字但未收到反馈。

## 记录与数据

识别记录位于应用数据目录的 `history.json`，最多 200 条，可在“识别记录”查看、复制和清空。它可能含口述的代码或个人信息，按私人文件管理。错误情况下也可能记录用户本轮正文；不要把整个应用数据目录上传到 Issue。

外观设置位于 `config.json`，日志为 `codex-voice-input.log`。配对码不保存，不写日志。旧应用的加密 MCP 缓存不用于当前功能，也不会因安装源码而删除。

换机器人或换电脑以重新无线配对为准。现在不是设备列表管理器；不要期待同时连接多台机器人。
