# 项目介绍与贡献边界

## 项目目标

把现有 ESP-SparkBot 桌面机器人改造成电脑的实体语音输入终端：保留原有聊天能力，在需要口述时切到听写模式，正文先形成草稿，明确确认后提交。

这是基于开源项目的应用集成与二次开发作品。关注设备端、语音服务和 Windows 输入之间的完整交互，以及配对、误触、断线和实际交付的问题。

## 可以看到的成果

- 机器人固件：聊天、时钟、Codex 输入、木鱼、骰子、2048、摄像头七个页面。
- 无线听写：一次配对、自动连接、逐句输入、明确发送、退出恢复聊天。
- 设备交互：电容触摸切页/确认、BMI260 手势、摄像头方向适配、电量显示。
- 电脑程序：机器人连接、原生文字输入、识别历史、托盘和安装/便携入口。
- 源码、协议、测试与版本边界说明。

## 开源复用与项目改造

| 部分 | 上游提供 | 本项目工作 |
| --- | --- | --- |
| 小智固件 | 语音/音频框架、联网、聊天、工具框架及设备基础能力 | 接入固定听写模式、无线文字链路、模式期间的工具阻断与本地反馈 |
| 原厂 SparkBot 示例 | 时钟、木鱼、骰子、2048 的逻辑/素材及硬件参考 | 适配到当前 LVGL/小智工程，整合菜单，调整手势、触摸和显示 |
| Windows 上游应用 | 桌面应用基础和原生输入实现 | 收敛为机器人输入，整合配对、TLS、轮次队列、机器人状态和公开接入规范 |
| 官方库与驱动 | ESP-IDF Security2/TLS、Bosch SensorAPI、TinyGL、电量估算组件 | 集成、配置与板型适配，保留来源和许可证 |

项目使用 AI 辅助开发。贡献展示以仓库中的具体改造和调试过程为依据；不把上游模型、官方安全算法、原厂游戏或驱动写成从零自研成果。

## 已有能力与边界

目前展示的是语音服务集成、设备通信、状态管理和应用交付。识别与聊天依赖小智在线服务；没有自行训练语音/大语言模型，也没有在本项目中实现 RAG 或多智能体系统。

机器人负责语音和实体交互，电脑负责当前窗口中的输入。原生输入事件成功不等于 Codex 服务端已经收到任务，使用者仍需核对屏幕。
