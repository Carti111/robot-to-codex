# Reused factory functionality

Factory source is esp-friends/esp_sparkbot example/factory_demo_v1, commit d42c5b43e25168fa3592a9c3d113ab5631f47023. The workspace retains the original repository and LICENSE.factory-functions retains its Apache-2.0 license.

https://gitee.com/esp-friends/esp_sparkbot

- Wooden fish uses the original ui_img_muyu_png artwork, muyu.wav sound and scale/floating-merit animation. RGB565 with alpha is composited on the original black background and pre-scaled to the original 200px display size for LVGL 9.
- Clock uses the original ComfortaaBold75 and OPPOSans fonts, white hours and gold minutes. The upper section displays real date and weekday. No sample weather or temperature values are rendered.
- 2048 retains the original movement and merge rules, board proportions, score presentation and color palette. LVGL 9 labels replace the LVGL 8 custom button-matrix draw callback. Small fonts are used for four-digit tiles.
- Dice uses the same six BMP textures, cube geometry, projection and TinyGL library as the factory implementation. SparkDice is an LVGL 9 image wrapper around that renderer. TinyGL version 0.4.1~1, commit 7ca5c2622acedc71a44a3a0b0ab581671b575c16 and original MIT notices are in components/tinygl.
- scripts/prepare_spark_factory_assets.py reproduces converted artwork and fonts from the retained factory repository. Only image storage, includes and font fallback are adapted. Original artwork is preserved.

Bosch BMI270 SensorAPI is pinned with original BSD-3-Clause notices under components/bmi270_sensorapi. The assembled robot reports BMI260 ID 0x27. It reuses the Bosch BMI2 base accelerometer/gyroscope API with the separately licensed, pinned linux-firmware BMI260 configuration image. Original driver sources remain unchanged.

The UI snapshot test compiles the actual production feature pages, font bitmaps, original textures and LVGL software renderer. It checks resting wooden-fish and dice pages for unnecessary refreshes. It does not replace hardware motion, touch, sound or unplugged wireless acceptance.

Phone-hold 2048 controls reuse the factory app_imu.c axis profile (pitch/gyro Y for up-down, yaw/gyro Z for left-right) and Bosch +/-2000 dps conversion. Bounded short-gesture integration replaces the first prototype's absolute gravity-angle/recentering requirement. A motion stroke must integrate at least 20 degrees on one axis before emitting a direction. Axis rates below 20 dps are excluded from integration, so minor low-speed hand motion cannot build up into a step. A sustained rotation remains latched to that step. A natural speed valley followed by renewed motion, or a deliberate dominant-axis direction change, starts the next stroke with a 240ms minimum step interval. This replaces the overly sensitive fixed-period repetition while avoiding a requirement to return to an exact pose. This supports left/right turning even when gravity does not change.

The camera feature requests vertical row reversal and horizontal mirroring while copying its RGB565 preview. The normal camera capture path and stored camera orientation settings are independent of that per-preview transform. camera_preview_test.cpp exercises orientation, byte order and output bounds.

The chat homepage uses SparkDisplay, a board-local extension of the existing SPI chat display. It applies a black dark theme and appends a compact battery percentage after the existing battery icon. Battery readings now use the factory app_power primary path: external ADC2 channel 3 (GPIO14), 12dB attenuation, 100k/100k divider, calibrated ESP-IDF handles and the unmodified espressif/adc_battery_estimation component. The factory manifest requires ^0.2.0; the installed 0.2.2 is within that range. Defaults remain Model 1, ten ADC readings, a 0.2 capacity low-pass coefficient and a ten-point/20-second software charge-state window. A board-local five-second startup delay and three stable voltage readings prevent invalid startup samples from seeding the component. Cached capacity and charge state are shared by icon, percentage and status reads at one estimation call per second. The temporary 3.1V-to-4.2V linear fallback has been removed from normal operation. scripts/test-battery-estimator.ps1 compiles the unmodified upstream C implementation with deterministic ADC/time fixtures, checking exact OCV points, filters, directional consistency, ADC errors and the observed 200-second low-value latch. Charge-completion GPIO remains unconfirmed; an OCV estimate reaching 100% alone cannot verify physical charge completion. Native LVGL tests exercise production homepage styling and percentage placement with a shared-chat platform fixture, including 75%, 8%, 100%, unavailable readings and unchanged-state redraw suppression.
